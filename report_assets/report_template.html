PROJECT REPORT
ResuMind AI — Advanced AI Resume Analyzer & ATS Optimizer
Bharat Cares x IBM GenAI Program
1. Application Overview & Tech Stack

ResuMind AI is a modern, high-performance, and privacy-focused web application designed to grade your resume, evaluate ATS compatibility, identify grammar issues, discover missing keywords, and practice tailored mock interview questions. The application parses resume text directly from uploaded PDF or DOCX files and processes them entirely in-memory with zero permanent storage or database footprint, ensuring maximum data privacy.

1.1 Tech Stack
Backend Node.js, Express, Multer (in-memory file handling using MemoryStorage)
LLM Integration Native fetch handlers connecting to Google Gemini API (gemini-3.5-flash / gemini-3.5-pro), OpenAI API, Anthropic Claude, OpenRouter, and xAI Grok
Database None (Privacy-first design; all operations are strictly in-memory and transient)
Auth & Security Strict file type filtering, size validation (10MB limit), and in-memory parsing to prevent persistent file storage risks
Config python-dotenv equivalent in Node.js (dotenv) for managing server port, active AI providers, models, and API keys
Frontend React (v19) SPA, Vite, Tailwind CSS v4, and Lucide Icons (premium dark-mode themed interface)
Frontend libraries (CDN) Tailwind CSS v4 (native build system), Lucide React (vector iconography), canvas-based inline circular progress elements
Deployment Render (onrender.com) using render.yaml web service config

2. Prompting Strategy & Frameworks Used

The application bypasses heavy orchestration frameworks (like LangChain) to maintain a fast, stateless, and lightweight footprint. It communicates directly with LLM API endpoints using custom-engineered system instructions that enforce structural JSON responses.

2.1 Structured Schema Prompting

A single, comprehensive system prompt is supplied during completion calls. It instructs the AI to evaluate the candidate's resume text and return a strict, pre-defined JSON schema containing scoring metrics, strengths, weaknesses, missing keywords, and recommended projects/certifications.

SYSTEM_PROMPT = `You are an expert ATS (Applicant Tracking System) Resume Reviewer and Career Coach. Analyze the uploaded resume text and provide a structured, detailed review. You must return ONLY a valid JSON object matching the schema below. Do not wrap your output in markdown formatting, your response must be parseable directly. Expected JSON Schema: { "overall_score": <number 0-100>, "ats_score": <number 0-100>, "grammar_score": <number 0-100>, "skills_score": <number 0-100>, "strengths": [<list of strengths (3-5)>], "weaknesses": [<list of areas of improvement (3-5)>], "missing_skills": [<list of critical missing skills>], "recommended_projects": [<list of 2-3 specific project ideas>], "recommended_certifications": [<list of suitable certifications>], "best_job_roles": [<list of 3-5 job titles>], "resume_summary": "<summary of current resume summary>", "improved_summary": "<rewritten professional summary>", "interview_questions": [<list of 3-5 practice questions>], "final_suggestions": [<list of actionable next steps>] }`
2.2 JSON Response Cleaning

A sanitization function in the backend ensures the robustness of the system by cleaning markdown wraps (such as ```json ... ```) or any preamble and trailing text before passing the payload to JSON.parse().

4. Application Architecture

ResuMind AI operates on a clean client-server architecture. The browser-based frontend handles file selection, basic pre-parsing validations, and data visualization. The Express backend handles PDF/DOCX text parsing and interacts with the AI services.

Browser (React v19 + Tailwind CSS v4) | | HTTP POST /analyze (Multipart Form-Data with PDF/DOCX File) v Express Monolith (backend/index.js) |-- parser.js (Reads PDF.js / Mammoth.js in-memory buffers) |-- ai.js (Appends text to SYSTEM_PROMPT, handles API calls) v Configured AI Provider (e.g., Google Gemini API) | | (Analyzes Resume Text & Returns Structured JSON Output) v Browser (Renders Circular Scores & Analytics Dashboard)
4.1 Data & Session Flow
  • Transient Processing: Document parsing utilizes multer.memoryStorage(). The buffer is immediately read to text and not committed to any database, preserving user confidentiality.
  • Stateless Operations: No backend user session databases or trackers are needed. Text analysis is conducted in a single stateless request-response transaction.
4.2 State Management

Analysis data returned from the backend is stored inside the React parent component's local state and passed down to nested dashboard panels. Theme changes (Dark/Light mode) are persisted in the user's browser via localStorage.

5. Challenges Encountered & How They Were Resolved
Challenge Resolution
PDF Layout Spacing Issues Certain PDF structures caused text extraction items to merge words. Resolved by joining items with explicit spacing characters page-by-page inside the parsePDF module.
Large Payload AI Timeouts Resumes with heavy content resulted in response delays. Settled on fast LLM models (specifically gemini-3.5-flash) to achieve completion responses under 3 seconds.
JSON Formatting Robustness Models occasionally wrapped JSON inside markdown blocks. Resolved by writing a regex-based extraction utility in ai.js to slice text between the first '{' and last '}' characters.
Vite Mono-Repo Assets Packaging and deploying frontend builds inside an Express directory structure. Resolved by writing root-level run scripts and static asset middlewares to serve compiled folders.
6. Key Learnings & Reflection
  • Transient Design Advantage: Processing uploads strictly in memory eliminates security compliance overheads, proving that databases are not always necessary for complex AI interactions.
  • Clean Architecture Flexibility: Isolating the AI API connectors inside a modular switch handler allows the application to adapt to other models instantly by editing a single configuration file.
  • Tailwind CSS v4 Velocity: Transitioning to Tailwind CSS v4 reduced build tool complexity and improved load speed, illustrating the value of keeping the dependency graph lightweight.
